# Отчет об использовании AI (AI_USAGE.md)

## 1. Какие части делались с AI
- Первичная генерация TypeScript-типов DTO и Enum на основе OpenAPI-схемы (`openapi.auctions.v0.json`).
- Создание заготовок FSD-структуры каталогов и UI-компонентов с соблюдением соглашения именования `*.component.tsx`.
- Подготовка базовых MSW-обработчиков (`handlers.ts`) и вёрстки компонентов списка и деталей.

## 2. Какое решение кандидат принял сам
- **Выбор архитектуры FSD (Feature-Sliced Design)** для масштабируемости разделения слоев (`app`, `pages`, `widgets`, `features`, `entities`, `shared`).
- **Двухуровневая стратегия мокирования**: сочетание MSW Service Worker с гибридным Vite DevServer middleware. Это решило специфическую проблему Chrome Incognito (баг MSW #2115), когда DevTools принудительно обходит Service Worker.
- **Инвалидация кеша TanStack Query**: организация инвалидации запросов списка, деталей и истории ставок синхронно после мутации `POST /auctions/{uuid}/bets`.
- **Zustand + Zod**: решение использовать Zustand для локального UI-состояния фильтров с типизацией через Zod.

## 3. Какие AI-предложения были отклонены
- AI предлагал использовать стандартные имена файлов (`AuctionCard.tsx`), однако согласно жесткому требованию ТЗ все React-компоненты были переименованы с суффиксом `*.component.tsx`.
- AI предлагал жестко привязать пути MSW к относительным строкам, что ломалось при открытой консоли Chrome. Было принято решение использовать строгую проверку путей и сервера.

## 4. Какие места кандидат проверял особенно внимательно
- **Точное соответствие OpenAPI-схеме**: проверка всевозможных `nullable` полей (например, `price_per_km`, `delay`, `your.last_bet`).
- **Сценарии с ограниченным доступом**: обработка флагов `can_set_bet: false`, `hide_bets_history: true`, `hide_points_address_and_contacts: true`, `no_view_cargo_price: true`.
- **Поведение при ошибках**: корректность генерации и отображения ошибки `422 ValidationProblem` при невалидной цене ставки.

## 5. Какие риски остались
- В случае развертывания проекта на продакшн-сервере без MSW, сетевые запросы будут уходить на реальный API. Потребуется настроить переключение `VITE_API_URL` в зависимости от окружения.

## 6. Что бы кандидат улучшил при наличии ещё одного дня
- Настроил бы полноценную интеграцию TanStack Router URL Search Params (`useSearch`), чтобы параметры фильтров напрямую синхронизировались с URL адресом в строке браузера.
- Добавил бы E2E-тесты на Playwright для проверки полных пользовательских сценариев (фильтрация -> открытие детальной карточки -> установка ставки -> обновление статуса на "Лидируете").
